# Notion Manual Pipeline v1 PRD

## 1. 한 줄 정의

PPT 매뉴얼을 업로드하면 슬라이드 텍스트, 화면 이미지, QR, 표, 어노테이션 후보를 추출하고, 사용자가 웹에서 검수한 뒤 Notion 매뉴얼 페이지에 실제 반영하는 내부 작업 도구.

## 2. 배경

현재 PPT 매뉴얼을 Notion으로 옮기는 작업은 다음 과정을 사람이 수동으로 수행하고 있다.

- PPT에서 설명 문구를 읽고 Notion 텍스트 블록으로 옮김
- 앱 화면, QR, 표 이미지를 직접 분리 crop
- 화살표/강조 박스/번호 어노테이션이 필요한지 판단
- 설명 텍스트까지 포함된 전체 슬라이드 crop을 피함
- 표는 가능한 경우 Notion table로 재작성
- Notion 하위 페이지 구조에 맞춰 페이지를 업데이트

이 도구는 위 과정을 웹에서 반복 가능하게 만들기 위한 것이다. 단순 파일 뷰어나 대시보드가 아니다.

## 3. 목표

### 제품 목표

- PPT 한 개를 입력하면 Notion 발행 가능한 변환 초안을 만든다.
- 사용자는 웹에서 변환 후보를 확인하고 필요한 부분을 수정할 수 있다.
- 검수된 결과는 Notion에 실제 발행된다.
- 작업 내역과 산출물을 다시 열어볼 수 있다.

### 품질 목표

- Notion에서 편집 가능한 텍스트는 이미지가 아니라 Notion 블록으로 만든다.
- 화면 이미지는 설명 텍스트를 포함한 전체 슬라이드가 아니라 의미 있는 이미지 영역만 사용한다.
- QR은 플랫폼/목적 단위로 분리한다.
- 표는 Notion table 변환을 우선한다.
- 자동 판단이 애매한 영역은 사용자가 웹에서 검수/수정한다.

## 4. 비목표

MVP에서 하지 않는다.

- 운영 대시보드
- 변환 성과 통계
- 협업 댓글/승인 워크플로우
- 복잡한 권한 관리
- 실시간 공동 편집
- AI 기반 완전 자동 문서 재작성
- PPT와 100% 동일한 시각 복제

## 7. 핵심 작업 흐름

### 7.1 작업 생성

1. 사용자가 PPT를 업로드한다.
2. 사용자가 Notion 대상 페이지 또는 DB를 지정한다.
3. 시스템이 변환 작업을 생성한다.
4. 원본 PPT는 Supabase Storage에 저장한다.

### 7.2 변환 실행

1. 사용자가 `실행`을 누른다.
2. 시스템이 변환 job을 생성한다.
3. 변환 worker가 PPT를 분석한다.
4. 슬라이드 렌더 이미지와 PPT 객체 정보를 생성한다.
5. 텍스트/이미지/QR/표/어노테이션 후보를 만든다.
6. 후보 결과를 Supabase DB/Storage에 저장한다.

### 7.3 결과 검수

1. 사용자가 작업 결과를 연다.
2. 슬라이드별 변환 결과를 본다.
3. 텍스트 블록 후보를 확인한다.
4. 이미지 crop 후보를 확인하고 필요하면 수정한다.
5. QR 분리 결과를 확인한다.
6. 표 변환 결과를 확인한다.
7. Notion 발행 대상 페이지와 매핑을 확인한다.

### 7.4 Notion 발행

1. 사용자가 `Notion 발행`을 누른다.
2. 시스템이 발행 payload를 생성한다.
3. Notion 페이지를 생성하거나 기존 페이지를 업데이트한다.
4. 이미지는 Notion file upload API로 업로드한다.
5. 발행 결과와 Notion block/page id를 저장한다.

### 7.5 재열람/재실행

1. 사용자는 작업 리스트에서 이전 작업을 다시 연다.
2. 결과를 확인하거나 재실행한다.
3. 재실행 시 기존 결과를 덮어쓰기 전에 새 버전으로 저장한다.

## 8. 상태 정의

| 상태 | 의미 | 사용자가 할 수 있는 일 |
| --- | --- | --- |
| `draft` | 업로드 입력 중 | 작업 생성 |
| `ready` | 작업 생성 완료 | 실행 |
| `running` | 변환 실행 중 | 상태 확인 |
| `review_required` | 변환 완료, 검수 필요 | 결과 확인/수정 |
| `ready_to_publish` | 검수 완료 | Notion 발행 |
| `publishing` | Notion 발행 중 | 상태 확인 |
| `published` | 발행 완료 | 결과 열람/재발행 |
| `failed` | 변환 또는 발행 실패 | 오류 확인/재실행 |

## 10. MVP 완료 기준

MVP는 아래를 실제로 수행해야 한다.

- PPT 파일을 업로드하고 Supabase Storage에 저장한다.
- 변환 job을 실행한다.
- 슬라이드 이미지를 렌더링한다.
- 슬라이드별 텍스트 후보를 추출한다.
- 최소 3종 후보를 분류한다: `text`, `image`, `qr`.
- 사용자가 결과 화면에서 후보를 확인할 수 있다.
- 사용자가 Notion 대상 페이지에 발행할 수 있다.
- 발행 결과가 작업 이력에 저장된다.
