# 수정 계획: 목차 계층화 변환과 계층 발행

## 1. 배경

현재 파이프라인은 변환·검수·발행의 골격은 갖췄으나, 결과물이 의도와 다르다. 슬라이드를 평면으로 나열하고, 발행 시 슬라이드 통짜 PNG와 단순 문단만 생성한다. 검수 화면에서 지정한 크롭 영역은 좌표로만 저장될 뿐 실제 이미지로 잘려 발행에 쓰이지 않는다.

목표 결과물은 기존에 수작업으로 만든 노션 매뉴얼 구조와 같다. 매뉴얼 허브 아래 목차 기준 카테고리가 있고, 카테고리 아래 기능별 서브페이지가 있으며, 각 서브페이지는 단계 위계 텍스트와 크롭된 화면 이미지로 구성된다.

## 2. 목표 동작

1. PPT를 변환하면 목차를 기준으로 카테고리와 기능이 자동으로 나뉜다. 표지와 목차 슬라이드는 본문에서 제외하되, 목차 텍스트는 카테고리·기능 트리를 만드는 근거로 보존한다.
2. 검수 화면에서 각 기능에 들어갈 화면을 크롭으로 확정한다. 확정된 크롭은 실제 이미지로 잘려 저장된다.
3. 발행하면 허브 페이지, 카테고리, 기능 서브페이지의 계층이 노션에 생성되고, 각 서브페이지에 단계 위계 텍스트와 확정된 크롭 이미지가 들어간다.

## 3. 현재와의 격차

- 목차 기반 계층이 없다. 슬라이드를 카테고리·기능으로 묶는 모델과 파싱이 없다.
- 크롭이 좌표 저장에 그친다. 좌표로 이미지를 잘라 저장하는 단계가 없고, 발행은 잘린 이미지를 참조하지 않는다.
- 발행이 평면적이다. 카테고리·서브페이지 계층, 단계 번호 목록, 주의 콜아웃이 없다.

## 4. 데이터 모델 변경

기존 `manual_slides`를 유지하면서 계층 테이블을 추가한다.

- `manual_categories`: 매뉴얼(task)에 속한 목차 카테고리. `task_id`, `sort_order`, `title`, `source` (toc 또는 manual).
- `manual_functions`: 카테고리에 속한 기능. 노션 서브페이지 한 개와 1대1 대응한다. `category_id`, `sort_order`, `title`.
- `manual_slides`에 `function_id`(nullable)와 `slide_role`(cover, toc, section, content)을 추가한다. 표지·목차 슬라이드는 `function_id`가 비고 본문에서 제외된다.
- `manual_assets`는 슬라이드 단위를 유지한다. 발행 시 기능에 속한 슬라이드들의 승인된 asset을 모은다. 잘린 이미지는 `storage_path`에 저장한다.

기존 `manual_notion_blocks`는 `function_id`로도 묶을 수 있게 컬럼을 추가한다.

## 5. 변환 worker 변경

### 5.1 슬라이드 역할 판정

`inferSlideRole`을 확장해 표지, 목차, 섹션 표지, 본문을 구분한다. 목차 슬라이드는 번호 목록 텍스트를 카테고리·기능 후보로 추출한다. 섹션 표지 슬라이드(제목이 `01.` `02.` 형태)는 카테고리 경계로 본다.

### 5.2 카테고리·기능 트리 생성

목차 텍스트와 섹션 표지에서 카테고리명을 그대로(verbatim) 가져온다. 추론으로 이름을 바꾸지 않는다. 본문 슬라이드는 제목의 기능명으로 기능에 매단다. 연속한 동일 기능명은 한 기능(한 서브페이지)으로 병합한다.

자동 분할 결과는 확정이 아니라 후보다. 검수 화면에서 사람이 슬라이드의 소속 카테고리·기능을 재배치할 수 있다.

### 5.3 본문 블록 생성

본문 텍스트를 위계로 분류한다. 단계(`1.` 패턴)는 numbered list, 하위 항목은 그 단계의 children, 주의·참고·TIP은 callout, 일반 설명은 paragraph로 만든다. 제목은 서브페이지 제목으로 올린다.

## 6. 크롭 실제 적용

`sharp`를 도입한다. 검수에서 asset이 승인되면 해당 슬라이드 렌더 PNG를 crop_box(퍼센트 좌표) 기준으로 잘라 `manual-assets` 버킷에 저장하고 `storage_path`를 채운다. 크롭 실행 시점은 두 가지 중 하나로 한다.

- 승인 시 즉시: asset 승인 PATCH에서 잘라 저장한다.
- 발행 직전 일괄: 발행 payload 생성 단계에서 승인된 asset을 한 번에 잘라 저장한다.

발행 직전 일괄을 기본으로 한다. 검수 중 좌표를 여러 번 바꾸므로, 최종 확정분만 자르는 편이 낭비가 없다.

## 7. 계층 발행

REST로 다음 트리를 만든다. 컬럼 2단 배치 같은 시각 디테일은 후속으로 두고, 우선 계층과 내용을 정확히 만든다.

1. 허브 페이지를 대상 페이지 아래에 생성한다.
2. 카테고리마다 허브 아래에 카테고리 페이지를 생성한다.
3. 기능마다 카테고리 아래에 기능 서브페이지를 생성한다.
4. 기능 서브페이지 본문에 단계 번호 목록, 하위 항목, 주의 콜아웃, 확정된 크롭 이미지를 읽는 순서대로 넣는다.

이미지는 통짜 슬라이드 렌더가 아니라 잘린 asset을 쓴다. 노션 네이티브 파일 업로드로 올려 만료 없는 첨부로 만든다. 발행한 노션 page와 local 엔티티의 매핑을 저장해, 재발행 시 새로 만들지 업데이트할지 판단할 근거를 남긴다.

## 8. 검수 화면 변경

- 좌측에 목차 트리(카테고리 → 기능)를 표시하고, 슬라이드를 기능에 끌어다 재배치할 수 있게 한다.
- 크롭은 드래그·리사이즈로 조절한다. 크기·위치 숫자 입력은 편집이 아니라 현재값 표시로 바꿔, 조절 경로를 드래그로 일원화한다.
- 발행 전 preview에서 카테고리·서브페이지 계층과 각 페이지의 블록 구성을 확인한다.

## 9. 작업 순서

1. 스키마 확장(카테고리·기능 테이블, 슬라이드 역할·소속 컬럼, asset storage_path 사용).
2. worker의 목차 계층화와 본문 위계 분류.
3. 계층 발행.
4. 크롭 실제 적용.
5. 검수 화면 정리.

구조가 먼저 서야 이미지를 어디에 넣을지가 정해지므로 계층화와 발행을 앞에 둔다.

## 10. 완료 기준

- 변환 결과가 카테고리·기능 트리로 나뉜다. 표지·목차는 본문에서 빠지되 카테고리 정보로 쓰인다.
- 검수에서 확정한 크롭이 실제 잘린 이미지로 저장된다.
- 발행 결과가 허브·카테고리·기능 서브페이지 계층으로 생성되고, 단계 위계 텍스트와 크롭 이미지를 포함한다.
- 통짜 슬라이드 이미지나 설명 텍스트가 이미지에 갇히는 발행이 기본 동작이 아니다.
